# Testing strategy

The safety rules (no remote high-risk approval, single-use decisions) must have automated tests before phase 4 ships.

```mermaid
flowchart LR
    C[Contract: schema fixtures] --> U[Unit: policy, validation, rendering logic]
    U --> I[Integration: hook → daemon → fake BLE peer]
    I --> H[Hardware-in-the-loop: real buddy]
```

| Layer | What to test | Tool | Run |
| :--- | :--- | :--- | :--- |
| Contract | Valid fixture per type passes; each invalid fixture fails; scenarios emit only valid events | `node:test` + ajv | `pnpm test` |
| Unit (daemon) | Risk policy classification; decision validation (pending, expiry, single use, high-risk approve rejected); Swift types vs. shared fixtures; `HiloStore` (tasks, session recording and auto-link, agreements, commits, activity spans, session tokens, week report and resume text, migrations); recorder → snapshot `hilo`; usage tracker, transcript tokens, git capture, config, control ops and pairing flow; secret redaction (`Redactor`, with a redacted shared fixture); LaunchAgent plist and `launchctl` sequence (fake runner); Pomodoro saved with its finished cycles and restored after a restart (no lost or repeated cycles); `AppleScriptPlayer` with scripted apps (none open, Automation denied and retried, app quitting midway, playing over paused, 5 s timeout) and a slow player that must not block the coordinator; face chunks re-sent after a buddy reboot; covers (96×96 in 5 chunks under the cap, shared fixture hash, named in `media.now_playing` once read and sent only on request for the track playing now, a late cover for a previous track dropped, Spotify URLs only from `https://i.scdn.co`, Music.app raw artwork, faked players and downloads) | Swift Testing | `scripts/swift-test.sh` |
| Unit (firmware) | `buddy_model` (portable C) and the demo feed (2 h simulated, no rejected message): every shared fixture (valid accepted, invalid rejected except unknown fields), sort order, Home text, pet states, timers (idle 60 s, reminder 25 s, hold 900 ms, long press 650 ms, sleep clock shift), decisions; every message the buddy emits is validated against the schema; two Macs over real connections (one picture each, forgetting one frees its slot and its half-received picture, a third Mac turned away while both are linked, rotation in slot order); Pomodoro edges (flip exactly at `ends_at`, `updated_at` ties, counting alone through a dropped link, no start without the clock); link times stamped once the clock is known; covers (asked once from the Mac that names it, assembled and shown only for the track that names it, wrong hash / gap / out of range dropped, a new Mac in the slot drops a half-received one) | clang + UBSan, minimal harness in `firmware/test/` | `scripts/firmware-test.sh` |
| Integration | Hook payload → event → fake peripheral; reconnect sends `snapshot`; deny, single use, question answer echoed in `updatedInput`, mismatched answers, expiry at 600 s (fake clock) | Swift Testing (`Coordinator` with fake link, clock, presence); a real debug `hilod --stdout` driven by `hilo hook` and `hilo buddy` (deny, question, high-risk approve ignored, redaction, schema check) | `scripts/swift-test.sh`, `scripts/hilod-e2e.sh` |
| Visual parity | Firmware screens vs. `prototypes/buddy-sim.html` | Host render of the real LVGL UI and model to PNG for layout and text (`scripts/firmware-render.sh`: idle rotation, Focus and Music scenes, the latter with a synthetic cover); colour, contrast and feel on the board ([hardware checklist](#hardware-checklist)) | `scripts/firmware-render.sh` |
| Hardware | Pairing, two Macs, range loss, battery alerts, touch and timing feel | [Hardware checklist](#hardware-checklist) | — |

## Hardware checklist

Things only the board can confirm. Run them once flashing is approved; tick them in the commit that confirms them.
